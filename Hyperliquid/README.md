# Hyperliquid

Сбор данных CoinGlass о позициях Hyperliquid и формирование отчёта.
Команда `/activate` после сбора строк запрашивает публичный `clearinghouseState`
Hyperliquid для каждого уникального адреса и perp DEX. Цена входа берётся из
`entryPx` открытой позиции, совпадающей по адресу, активу и направлению. Она
появляется на листах «Позиции» и «По размеру позиции». Если позиция уже закрыта,
сменила направление или API недоступен, ячейка остаётся пустой; лист «Сводка»
показывает охват проверки. Проверка выполняется при каждом запуске `/activate`.

Лист «Снимки крупных» хранит по семь крупнейших лонгов и шортов BTC и ETH
в пределах 7% на каждом запуске. Короткая метка кошелька устойчиво образуется из адреса;
полный адрес остаётся в таблице. Сравнение количества монет по снимкам является
наблюдением: выход из топ-7 не доказывает закрытие позиции.

Лист «История кошельков» показывает подтверждённые исполнения BTC и ETH и
снимки открытых позиций этих монет по кошелькам, когда-либо попавшим в эти топ-7. При каждом
`/activate` сборщик проверяет публичную историю исполнений Hyperliquid с
последней успешной проверки и сохраняет её в `wallet-activity.sqlite3`.
Из `startPosition`, стороны и размера исполнения определяется открытие,
увеличение, сокращение или закрытие. Реализованный PnL относится к отдельному
исполнению; комиссия показана отдельно, фондирование не учтено. Ликвидация
отмечается лишь при признаке в ответе API. Если историю за интервал получить
не удалось или достигнут лимит доступной истории API, в Excel появляется
строка с пробелом проверки, а время последней полной проверки не сдвигается.
Проверенное наблюдение начинается с момента развёртывания этой функции:
прошлые исполнения не восстанавливаются как полная история.
Данные по другим монетам, сохранённые до ограничения списка BTC и ETH,
остаются в базе, но больше не проверяются и не выводятся в новые отчёты.

На листе «Позиции» ширина столбцов A–F равна 10, H — 35,7, I — 50.
