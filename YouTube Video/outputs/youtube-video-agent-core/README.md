# Ядро агента «Сохранение видео YouTube и Instagram»

Изолированный внутренний HTTP API: принимает ссылку на один общедоступный ролик YouTube либо публичный Instagram Reel/видеопубликацию, создаёт задание, сохраняет доступный видеофайл и по желанию распознаёт речь в отдельный UTF-8 `.txt` с временными метками. Авторизация платформ, cookies, пароли, обход DRM, геоблокировок и приватного доступа отсутствуют.

Важно: сервис не гарантирует доступность любой публичной публикации. YouTube или Instagram могут ограничить конкретный поток, потребовать вход, проверку возраста, подтверждение человека или изменить протокол. Instagram особенно часто ограничивает серверные запросы без входа. Пользователь должен иметь право сохранять конкретное видео и соблюдать правила платформы и применимое законодательство.

## Что защищено

- принимаются только прямые HTTPS-ссылки на одно видео YouTube либо один Instagram Reel/видеопост с корректным идентификатором;
- URL нормализуется до канонического вида, пользовательские данные, порт, IP, плейлист и произвольный сайт отклоняются;
- `yt-dlp` запускается без конфигурации пользователя, cookies и `.netrc`; если YouTube отклоняет обычный анонимный запрос как автоматический, агент один раз повторяет его через встроенный `web_embedded`-клиент, который не использует Google-аккаунт и работает только для роликов с разрешённым встраиванием;
- при выборе потока приоритет отдаётся H.264/AAC; полученный VP9, AV1 или несовместимый контейнер автоматически перекодируется в H.264/AAC MP4 для нормального воспроизведения в браузерах, телефонах и стандартных проигрывателях;
- есть лимиты длительности, размера, свободного диска, времени и повторных попыток; когда Instagram не сообщает длительность заранее, она обязательно проверяется через `ffprobe` после загрузки, а превышающий лимит файл удаляется;
- временный каталог и имя файла случайны, выдача разрешена только владельцу задания;
- один активный запрос на пользователя, почасовая квота заданий и суточная квота байтов;
- файлы автоматически удаляются после TTL при следующем обращении к API.

API рассчитан на один процесс `uvicorn`. Для нескольких процессов/серверов состояние заданий и блокировки следует перенести в Redis/очередь задач; SQLite уже хранит квоты между перезапусками.

## Запуск

Нужны Python 3.11+, `ffmpeg`/`ffprobe` и свободный локальный диск. Распознавание выполняет `faster-whisper` локально на CPU; аудио не отправляется во внешний сервис. При первом запросе выбранная модель загружается в `YTA_MODEL_DIR`.

```bash
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[test]'
cp .env.example .env
```

Задайте случайный `YTA_API_KEY` длиной не менее 24 символов и загрузите переменные окружения удобным для системы способом. Затем:

```bash
YTA_API_KEY='replace-with-a-long-random-secret' \
YTA_DATA_DIR='/srv/youtube-agent/var' \
uvicorn youtube_agent.app:app --host 127.0.0.1 --port 8091 --workers 1
```

Сервис следует слушать только на loopback/private network и публиковать через серверную часть сайта. Не помещайте `YTA_API_KEY` в JavaScript браузера.

## Интерфейс интеграции

Сервер сайта аутентифицирует посетителя, удаляет любой присланный браузером `X-User-ID`, затем сам добавляет стабильный внутренний ID пользователя и секретный Bearer-токен.

1. Создать задание:

```http
POST /api/v1/jobs
Authorization: Bearer <YTA_API_KEY>
X-User-ID: <stable-site-user-id>
Content-Type: application/json

{"url":"https://www.youtube.com/watch?v=BaW_jenozKc","extract_text":true}
```

Ответ `202`: `{"id":"...","status":"queued",...}`.

2. Опросить `GET /api/v1/jobs/{id}` с теми же заголовками. Состояния: `queued`, `running`, `transcribing`, `ready`, `failed`. При `ready` ответ содержит `download_url`, а после успешного распознавания — также `transcript_url` и определённый язык. Ошибка распознавания не уничтожает уже готовое видео и возвращается отдельно как `transcript_error`.

3. Сервер сайта проксирует `GET /api/v1/jobs/{id}/file` и, если он создан, `GET /api/v1/jobs/{id}/transcript` пользователю как вложения. Браузерные кнопки включаются только при `status=ready`.

Пример server-side JavaScript:

```js
const headers = {
  Authorization: `Bearer ${process.env.YTA_API_KEY}`,
  "X-User-ID": authenticatedUser.id,
};
const created = await fetch("http://127.0.0.1:8091/api/v1/jobs", {
  method: "POST",
  headers: {...headers, "Content-Type": "application/json"},
  body: JSON.stringify({url: submittedUrl, extract_text: true}),
});
```

## Проверки

```bash
pytest -q
```

Ручная сетевая проверка YouTube использует короткий ролик `ptd1NN40vMw`, чьи метаданные YouTube на момент проверки указывают лицензию Creative Commons Attribution. Она не запускается автоматически. Для Instagram автоматический реальный тест загрузки не включён: используйте собственную или явно разрешённую публичную публикацию.

```bash
python scripts/public_smoke_test.py
```

## Эксплуатационные ограничения

- дефолт: до 4 часов, 2 ГиБ на файл, 20 заданий в час и 4 ГиБ в сутки на пользователя;
- распознавание речи по умолчанию доступно для роликов до 2 часов, использует модель `small` и может работать заметно дольше самой загрузки;
- автоматическая расшифровка может ошибаться при шуме, музыке, нескольких говорящих, редких именах и плохом звуке; это не заверенная стенограмма;
- остаётся минимум 3 ГиБ свободного диска; таймаут загрузки 30 минут;
- готовый файл хранится 1 час, но удаление выполняется лениво при следующем API-запросе; для строгой уборки добавьте системный таймер, удаляющий старые подкаталоги `var/jobs`;
- журнал reverse proxy не должен сохранять Bearer-токен; URL ролика также лучше не включать в логи;
- обновляйте `yt-dlp` осознанно после тестирования: YouTube регулярно меняет выдачу потоков.
- безопасный `web_embedded`-повтор не является обходом блокировки IP и не гарантирует доступ ко всем роликам. Агент намеренно не принимает Google-пароль или браузерные cookies; если YouTube блокирует и встроенный клиент, используйте локальное сохранение разрешённого материала либо повторите позже.
